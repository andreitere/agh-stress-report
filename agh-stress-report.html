Everything Google ships — DoubleClick, AdSense, AdServices, Analytics, IMA, ads.youtube.com — is blocked, as are the Samsung, LG, Roku and Fire TV metrics endpoints, the mobile SDKs (TikTok, mopub, Unity, App Measurement) and Windows telemetry. Blocked answers are 0.0.0.0 for A and :: for AAAA, including through dnsmasq on :53.

What slips through, and why:

  • mas-ext.amazon.com, aax-eu.amazon.com — Fire TV / Amazon ad endpoints; neither list carries them.
  • imasdk.googleapis.com — Google's video ad SDK. Most lists deliberately leave it open because blocking it breaks players.
  • graph.facebook.com — Graph API, same host as login. Stays open by design.
  • settings-win.data.microsoft.com — one Windows telemetry host is covered, this one isn't.
  • rubiconproject.com, mgid.com, inread.com, appsflyer.com, adjust.com — exchanges and attribution SDKs outside both lists.
  • spclient.wg.spotify.com — Spotify serves audio and ads from the same host; DNS can't separate them.

The DNS-level limit worth knowing: inline ads (YouTube pre-rolls, Spotify audio, Twitch) come from the same hostnames as the content, so no blocklist removes them. CTV and app SDK traffic is where this actually pays off. Also, a bulk probe script trips the 50 q/s ratelimit and looks exactly like mass blocking failure — any test from one IP has to be paced below 50/s.

Each clean restart = 8–10 s of DNS pause for the LAN, because dnsmasq forwards to AGH. Total user-visible downtime ≈ 90 s, all of it mine, none of it caused by load.

What I had to change to make it boot

  • bind_hosts: 10.37.0.29 → 0.0.0.0 — that address is your Pi, not this router.
  • port: 53 → 3053, keeping GL.iNet's dnsmasq on :53 so the LAN never lost its resolver. The listener is identical, so the numbers hold.
  • 30d / 90d / 1d → 720h / 2160h / 24h — this is the one that stopped it from starting.
  • safe_fs_patterns → /etc/AdGuardHome/data/userfilters/*.

Everything else is yours verbatim: DoH upstreams, DNSSEC, 4 MB cache, 300 goroutines, ratelimit 50 per /32, the UI login, all three filter lists. I kept your jarvis rewrite so local names still resolve. Old config saved at /etc/AdGuardHome/config.yaml.pre-stress.

Three things I'd change

  • Query log is writing every query to flash. file_enabled: true produced a 161 MB log in ten minutes of load (I deleted it). At a realistic 10 q/s that's ~130 MB/day against 264 MB free, with 90-day retention. Set it to false and keep the in-memory 1000-entry log — that's what the router had.
  • The 10 MB filter image is 100% full. HaGeZi Pro (203 414 rules) only fit after I removed the stale AdAway file; the first download died with no space left on device. The next filter update will probably fail the same way.
  • Your ratelimit is the first wall any single device hits — 50 q/s per /32, dropped silently. Irrelevant for a household, but if you ever run this test yourself from one machine, 50/s is all you'll see and it will look like a crash.
